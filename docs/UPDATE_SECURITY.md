# Безопасность обновлений

## Модель доверия

TypeFlow распространяется без Apple Developer Program. Поэтому первый
запуск не имеет нотарификации Apple и требует явного разрешения пользователя в
macOS. Встроенный канал обновлений решает другую задачу: уже установленное
приложение принимает только релизы, подписанные постоянным ключом проекта.

Корень доверия встроен в приложение:

- сертификат: `LocalSwitcher Local Development`;
- SHA-1 сертификата для code requirement:
  `BA582D2E25C17FAD3524B3C3CAED3748816D2E8A`;
- SHA-256 точных DER-байтов сертификата:
  `19C8CAEC20337D7749F5760844B6011364F463C0890268753EAE8E6334318F30`;
- сертификат действует до 7 сентября 2036 года;
- закрытый ключ хранится в Keychain разработчика и не входит в Git.

До истечения сертификата нужно выпустить переходную версию, которая доверяет
одновременно старому и новому ключу. Если старый ключ потерян до такого релиза,
существующих пользователей нельзя безопасно перевести на новый ключ через
автоматическое обновление - понадобится ручная установка.

## Проверки клиента

Клиент выполняет проверки в следующем порядке:

1. Загружает `version.json` и detached-файл `version.json.sig` по HTTPS.
2. Проверяет RSA/SHA-256 подпись точных байтов JSON встроенным сертификатом.
3. Отвергает неверную версию, URL вне официального репозитория и некорректный
   SHA-256.
4. Отдельно для stable и beta запоминает максимальную увиденную версию фида и
   отвергает повторную выдачу более старого корректно подписанного манифеста.
5. Не устанавливает версию, которая не новее текущей.
6. Строит URL служебного DMG локально из проверенной версии и имени
   `LocalSwitcher-<version>.dmg`, а не принимает адрес загрузки из сети. Постоянный
   публичный файл `TypeFlow-macOS-arm64.dmg` предназначен для ручной установки.
7. Скачивает DMG потоково в приватный каталог `0700` с уникальным именем и
   ограничивает размер 256 МБ.
8. Сравнивает SHA-256 DMG с подписанным манифестом.
9. Монтирует служебный образ read-only и принимает только точный нессылочный путь
   `LocalSwitcher.app`. Перед заменой копирует его под физическим именем текущей
   установки, поэтому одинаково обновляются LocalSwitcher.app и TypeFlow.app.
10. Через Security.framework проверяет подпись исполняемого файла, всех ресурсов,
   вложенного кода, архитектур и структуру app-бандла. Code requirement закрепляет
   Bundle ID и SHA-1 сертификата, после чего клиент отдельно сравнивает полные
   DER-байты leaf-сертификата со встроенной копией по SHA-256.
11. Проверяет версию и Bundle ID из `Info.plist`.
12. Создаёт и повторно проверяет резервную копию установленного приложения.
13. Копирует новую версию в системный item-replacement каталог на том же диске,
    ещё раз проверяет подпись и только затем атомарно заменяет приложение.
14. Проверяет подпись и версию уже по установленному пути. При ошибке возвращает
    резервную копию до завершения старого процесса.

Поведение Security.framework с недоверенным self-signed сертификатом проверено
интеграционным тестом: корректно подписанный бандл принимается без записи
сертификата в trust settings, изменение подписанного `Info.plist` отвергается.

Подпись манифеста защищает от компрометации GitHub, DNS или CDN только пока
закрытый ключ проекта остаётся секретным. SHA-256 без подписи такой защиты не
даёт, потому что атакующий мог бы заменить одновременно DMG и хэш.

## Выпуск релиза

1. Убедиться, что рабочая копия чистая и получена из доверенной ветки.
2. Обновить `version.json` или `version-beta.json` и release notes.
3. Запустить все Swift-тесты, аудит коротких слов и `git diff --check`.
4. Собрать `./create_dmg.sh --self-signed` или добавить `--beta` для беты.
5. Скрипт обязан пересобрать приложение, проверить совпадение версии, подписать
   приложение постоянной identity, создать DMG, записать его SHA-256 и создать
   detached-подпись манифеста.
6. Независимо проверить SHA-256, `codesign --verify --deep --strict`, Bundle ID,
   версию и подпись манифеста.
7. Сначала загрузить в GitHub Release с тегом `v<version>` основной asset
   `TypeFlow-macOS-arm64.dmg` для ручной установки и служебный
   `LocalSwitcher-<version>.dmg` для встроенного апдейтера, затем одним коммитом
   опубликовать JSON и `.sig`. Нельзя публиковать новый манифест до появления
   соответствующих release assets.
8. Проверить обновление с предыдущей установленной версии и подтвердить запуск,
   Accessibility, Input Monitoring и event tap.

0.1.11 является bootstrap-релизом: в 0.1.10 updater был отключен, поэтому эту
версию нужно установить из DMG вручную один раз. Автоматический путь применяется
к последующим релизам.

## Совместимость переименования

Релиз 0.2.0 меняет пользовательское название LocalSwitcher на TypeFlow. Для
обновления существующих установок временно сохранены Bundle ID
`com.marko.localswitcher.app`, совместимая копия `LocalSwitcher.app`, сертификат
`LocalSwitcher Local Development`, прежние ключи UserDefaults и URL старого
репозитория в подписанном stable-манифесте. Новый клиент принимает адреса обоих
репозиториев. Основной файл релиза называется `TypeFlow-macOS-arm64.dmg`, а
`LocalSwitcher-0.2.0.dmg` является отдельным служебным образом для апдейтера.
Поле `sha256` подписанного манифеста относится к служебному образу, а
`public_sha256` - к публичному DMG ручной установки.

## Ограничения и реакция на инциденты

- Self-signed сертификат не даёт нотарификацию или доверие Gatekeeper при первой
  установке.
- При самом первом обращении клиента signed feed не доказывает свежесть: атакующий,
  который уже контролирует выдачу GitHub/HTTPS, может заморозить клиент на старом
  подписанном манифесте. После получения более новой версии локальная монотонная
  отметка блокирует такой откат, но ее может удалить локальный процесс пользователя.
- Автоматического отзыва ключа без инфраструктуры Apple нет.
- Резервная копия автоматически возвращается при ошибке замены, проверки или
  запуска relaunch-helper. Если новый процесс был успешно запрошен через
  LaunchServices, а затем аварийно завершился, автоматического watchdog-отката
  пока нет; проверенная копия остается в
  `~/Library/Application Support/LocalSwitcher/UpdateBackups` для восстановления.
- При подозрении на компрометацию закрытого ключа нужно немедленно прекратить
  публикацию, удалить update-манифесты из канала и потребовать ручную установку
  версии с новым встроенным ключом.
- Зашифрованная офлайн-копия закрытого ключа необходима для восстановления после
  потери Mac. Она не должна храниться в репозитории, облачной папке проекта,
  issue, CI-логах или командной строке.
